# Спектральный анализ затухающих колебаний для диагностики подшипника

Скрипт `spectral_bearing_diagnostics.py` выполняет спектральный анализ
вибрационных сигналов и по диагностическому отношению `R` определяет
наличие дефекта внутреннего кольца подшипника (компонент BPFI).

## Требования

- Python 3.8+
- `numpy`
- `matplotlib`
- `scipy` — только если нужно конвертировать исходные `.mat`-файлы CWRU в NPZ

```bash
pip install numpy matplotlib scipy
```

## Запуск

Скрипт ищет данные **относительно текущей рабочей папки**, поэтому
запускать нужно из папки проекта:

```bash
cd "E:\папка максима\Pyth\spectral_bearing_diagnostics"
python spectral_bearing_diagnostics.py
```

## Режимы работы

1. **Реальные данные CWRU.** Если найдены оба NPZ-файла (см. таблицу ниже),
   скрипт загружает из них канал DE.
2. **Демонстрационная модель.** Если файлов нет, сигналы генерируются
   воспроизводимо (seed = 42): 1797 об/мин, BPFI и периодические затухающие
   импульсы на резонансной частоте.

Режим отображается в первой строке вывода: `Источник данных: ...`.

## Зачем два файла

| Файл | Состояние подшипника |
|---|---|
| `1797_Normal.npz` | **эталон нормы** — исправный подшипник, 1797 об/мин |
| `1797_IR_7_DE12.npz` | **проверяемый** — дефект внутреннего кольца 0.007" (IR), канал DE, 12 кГц |

Роль файла определяется **именем** (списки `NORMAL_CANDIDATES` /
`FAULT_CANDIDATES` в начале скрипта), содержимое не анализируется.
Эталон нужен для наглядного сравнения на графиках: у исправного
подшипника на BPFI пика нет, а у дефектного он есть. Число `R` при этом
считается только от проверяемого сигнала.

## Требования к NPZ-файлам

| Файл | Пути поиска (первое совпавшее) |
|---|---|
| `1797_Normal.npz` | `Data\` → `Data\1797 RPM\` → рядом со скриптом |
| `1797_IR_7_DE12.npz` | `Data\` → `Data\1797 RPM\` → рядом со скриптом |

Содержимое файла:

- канал DE кладётся под ключом **`DE`** (если ключа нет — берётся первый массив);
- одномерный массив отсчётов (многомерный массив автоматически
  разворачивается в одномерный ряд);
- **частота дискретизации должна быть 12000 Гц** — параметр `FS = 12_000.0`
  зашит в скрипт, поэтому подходят только данные 12k-датчика DE
  (не 48k, не канал FE).

## Результаты на реальных данных CWRU

Данные: [97.mat](https://engineering.case.edu/sites/default/files/97.mat)
(норма, 1797 об/мин) и
[105.mat](https://engineering.case.edu/sites/default/files/105.mat)
(дефект IR 0.007", 1797 об/мин), сконвертированные в NPZ (см. ниже).

Вывод скрипта:

```
Источник данных: CWRU NPZ
f_r = 29.950 Гц
BPFI = 162.179 Гц
Найденный пик = 161.500 Гц
A_BPFI = 0.015516
A_фон = 0.000052
R = 298.745
Графики сохранены в: E:\папка максима\Pyth\spectral_bearing_diagnostics\results
```

Разбор:

| Параметр | Значение | Интерпретация |
|---|---|---|
| `f_r` | 29.950 Гц | 1797 об/мин — обороты двигателя ✓ |
| `BPFI` | 162.179 Гц | расчётная частота дефекта (5.415 × 29.95) |
| Найденный пик | 161.500 Гц | расхождение 0.68 Гц (0.4 %) — в пределах разрешения спектра |
| `R` | **298.745** | пик почти в 300 раз выше фона → **дефект** |

Расхождение пика с расчётным BPFI объясняется разрешением спектра
(`df = FS / N = 12000 / 24000 = 0.5 Гц`, сетка частот — шаг 0.5 Гц) и тем,
что коэффициент 5.415 — теоретический: в реальном эксперименте частота
дефекта немного смещается из-за фактических оборотов и проскальзывания.

### Контрольный эксперимент: дубликат нормы

Если положить вместо дефектного файла копию `1797_Normal.npz`:

- на графиках кривые полностью **слипаются** (оранжевая накладывается
  поверх синей одного и того же сигнала) — визуального отличия нет;
- `R` падает с 299 до **13** — дефектного пика нет.

| Данные в проверяемом файле | R |
|---|---|
| реальный дефект IR 0.007" | ≈ 299 |
| здоровый подшипник | ≈ 13 |

Разница в 20 раз — так метод и отличает норму от дефекта.

## Что такое R

`R = A(BPFI) / A_фон` — диагностическое отношение:

- **A(BPFI)** — амплитуда самого высокого пика в полосе `BPFI ± 8 Гц`;
- **A_фон** — медиана амплитуд в фоновой полосе `BPFI − 60 … BPFI − 20 Гц`.

Физически R показывает, во сколько раз линия на частоте дефекта выше
окружающего спектра. Оценку делят на локальный фон (а не на среднее по
всему спектру), чтобы метод одинаково работал на разных машинах, а фон
считают через медиану, чтобы случайные выбросы не размывали оценку.

- `R ≈ 1` — пика нет, подшипник исправен;
- `R` в десятки раз выше фона — повод насторожиться;
- `R` в сотни раз выше фона — явный дефект.

Порог в скрипт не зашит: его выбирают по статистике заведомо исправных
подшипников (обычно — втрое выше максимального «нормального» R).

## Подготовка данных CWRU (`.mat` → `.npz`)

Скрипт конвертации (сохраните рядом, например, как `mat2npz.py`):

```python
from pathlib import Path
import numpy as np
from scipy.io import loadmat

Path("Data").mkdir(exist_ok=True)

for src, dst in [
    ("97.mat", "Data/1797_Normal.npz"),
    ("105.mat", "Data/1797_IR_7_DE12.npz"),
]:
    m = loadmat(src)
    key = next(k for k in m if k.endswith("_DE_time"))  # X097_DE_time, X105_DE_time
    np.savez(dst, DE=np.asarray(m[key], dtype=float).ravel())
    print(dst, "ok, ключ:", key)
```

### Быстрый тест NPZ-ветки без реальных данных

```python
import importlib.util
import numpy as np

spec = importlib.util.spec_from_file_location("sbd", "spectral_bearing_diagnostics.py")
m = importlib.util.module_from_spec(spec)
spec.loader.exec_module(m)

t, normal, fault = m.make_demo_signals()
np.savez("Data/1797_Normal.npz", DE=normal)
np.savez("Data/1797_IR_7_DE12.npz", DE=fault)
```

## Алгоритм

1. Удаление среднего и окно Хэннинга.
2. Односторонний амплитудный спектр (`rfft`), нормировка на сумму окна.
3. Поиск локального максимума в полосе `BPFI ± 8` Гц.
4. Фон — медиана амплитуд в полосе `BPFI − 60 … BPFI − 20` Гц.
5. Диагностическое отношение `R = A(BPFI) / A_фон`.

## Возможные проблемы

- **`TypeError: amplitude_spectrum() missing ... argument: 'fs'`** —
  пропускался аргумент `fs` в вызове `amplitude_spectrum(fault)`; сейчас
  в вызов передаётся `FS` (ошибка исправлена).
- **Скрипт пишет `демонстрационная модель` вместо `CWRU NPZ`** —
  NPZ-файлы не найдены: проверьте имена и что запуск идёт из папки проекта.
- **На графиках одна кривая вместо двух** — файлы-дубликаты: проверяемый
  сигнал совпадает с эталоном.
- **Кириллица в выводе консоли отображается искажённо** —
  особенность кодировки Windows-консоли (cp1251), на расчёты и графики
  не влияет.
